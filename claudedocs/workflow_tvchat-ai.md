## Phase 1 — Local End-to-End Testing

**Goal:** Verify the full TV ↔ relay ↔ phone flow on your local network before deploying anything.

### Prerequisites
- Phone and dev machine on the **same WiFi network**
- Find your machine's local IP: `ipconfig` on Windows → look for IPv4 under your WiFi adapter (e.g. `192.168.1.42`)
- Set `VITE_COMPANION_URL=http://192.168.1.42:5174` in `packages/tv-app/.env.local`
- Set `VITE_RELAY_URL=ws://192.168.1.42:3001` in both `.env.local` files

### Tasks

| # | Task | Command | Expected |
|---|------|---------|----------|
| 1.1 | Start relay | `npm run dev:relay` | `tvchat relay listening on port 3001` |
| 1.2 | Start TV app | `npm run dev:tv` | Vite dev server on `http://localhost:5173` |
| 1.3 | Start companion | `npm run dev:companion` | Vite dev server on `http://localhost:5174` |
| 1.4 | Open TV app in browser | `http://localhost:5173` | Setup screen with QR code |
| 1.5 | Scan QR with phone | Phone camera | Companion opens in phone browser |
| 1.6 | Type and send API key | Companion | TV shows "Key accepted", navigates to chat |
| 1.7 | Type and send a chat message | Companion | Message appears on TV, Claude responds |
| 1.8 | Test live preview | Companion | Each keystroke updates TV InputBar |
| 1.9 | Attach and send an image | Companion | Image thumbnail shows on TV, Claude analyses it |
| 1.10 | Test model switcher | TV remote / keyboard arrow keys | Settings panel opens, model changes |
| 1.11 | Test conversation history | TV remote | New chat creates entry; selecting old one restores messages |
| 1.12 | Test error state | Enter a bad API key manually (edit localStorage) | TV shows error message, doesn't crash |

### Checkpoint
All 12 test cases pass locally before proceeding to deployment.

## Phase 2 — Deploy Relay (Render.com)

**Goal:** Get the WebSocket relay running at a public WSS URL.

### Tasks

| # | Task | Detail |
|---|------|--------|
| 2.1 | Push repo to GitHub | Create a new public/private GitHub repo, push the monorepo |
| 2.2 | Create Render.com account | render.com — free tier is sufficient |
| 2.3 | New Web Service from repo | Point at the GitHub repo; Render auto-detects `render.yaml` in root |
| 2.4 | Confirm settings from render.yaml | Root dir: `packages/relay`, build: `npm install`, start: `node src/server.js` |
| 2.5 | Wait for deploy | ~2 min first deploy |
| 2.6 | Verify health endpoint | `curl https://YOUR-SERVICE.onrender.com/health` → `ok` |
| 2.7 | Note the WSS URL | e.g. `wss://tvchat-relay.onrender.com` — this is your `VITE_RELAY_URL` |

### Notes
- Render free tier spins down after 15 min inactivity. First WebSocket connection may take ~10s to cold-start. Acceptable for personal use.
- To avoid spin-down: upgrade to Render Starter ($7/mo) or use a cron ping to `/health` every 10 min.

### Checkpoint
```
curl https://YOUR-RELAY.onrender.com/health  →  ok
```

## Phase 5 — Tizen Packaging

**Goal:** Package the TV app as a `.wgt` file installable on a Samsung TV.

### Prerequisites
- Tizen Studio installed: [tizen.org/development/tizen-studio](https://developer.tizen.org/development/tizen-studio)
- Samsung TV in Developer Mode: TV Settings → About This TV → tap Model Number 5× → Developer Mode ON → enter your PC's IP

### Tasks

| # | Task | Detail |
|---|------|--------|
| 5.1 | Copy dist into tizen folder | Copy all files from `packages/tv-app/dist/` into `packages/tv-app/tizen/` |
| 5.2 | Verify tizen/ folder contents | Must have: `index.html`, `config.xml`, `icon.png`, and `assets/` folder from the dist |
| 5.3 | Open Tizen Studio | File → Import → Tizen Web Project → point at `packages/tv-app/tizen/` |
| 5.4 | Connect TV | In Tizen Studio → Device Manager → Remote Device Manager → scan for TV on local network |
| 5.5 | Run on TV (debug build) | Right-click project → Run As → Tizen Web App → select connected TV |
| 5.6 | Test full flow on TV | Setup screen, QR scan, API key entry, chat — use real TV remote |
| 5.7 | Build release `.wgt` | Project → Build Signed Package → save `tvchatai.wgt` |
| 5.8 | Install release `.wgt` | Tizen Studio → Device Manager → right-click TV → Install App → select `.wgt` |

### config.xml reminder
Ensure `packages/tv-app/tizen/config.xml` still has:
```xml
<access origin="*" subdomains="true"></access>
```
Without this, the TV browser blocks all outbound requests.

### Checkpoint
- App appears in Samsung TV app list
- Full chat flow works end-to-end on the physical TV with TV remote
